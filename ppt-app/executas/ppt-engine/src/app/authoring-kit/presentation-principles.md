# Presentation Principles（演示文稿创作原则）

本文档是 Authoring Kit（创作套件）中的通用页面创作原则。它提供页面职责、信息层级和定量图表表达的判断规则，不是可直接运行的模板，也不替代 Workspace Style Guide（艺术指导）、Outline（大纲）或 Required Content（必要内容）。

当用户的明确请求、已确认的 Presentation Requirements（演示需求）或 Confirmed Outline（已确认大纲）与本文档的默认原则冲突时，遵循用户和已确认的 Workspace 决策；Workspace Style Guide 负责当前 Deck 的具体视觉表达。

## 页面角色与信息层级

- `Formal Presentation Cover（正式汇报封面）` 用于董事会汇报、经营复盘、项目报告、政策简报和严肃提案等正式场景。它通常识别演示文稿标题、主题或周期、日期和 `Presentation Identity（演示身份）`，不承担复杂正文分析。
- `Opening / Orientation Page（开场/导览页）` 负责说明议题、背景、中心判断或阅读路径，可以与第一个实质结论合并，不等同于正式封面。
- `Content / Analysis Page（内容/分析页）` 负责展开一个实质性核心信息，证据、图表、比较、指标、时间线和文字结构都应服务于该核心信息。
- `Closing / Next Action Page（收束/下一步页）` 负责总结结论、建议、决策或下一步行动；“谢谢”本身不是收束内容。
- 先判断当前页面职责，再决定版式。不要把普通开场页、内容页或收束页机械做成封面。
- 正式封面中的标题应最突出；主题/周期、日期和演示身份是次级元数据，不能与标题争夺视觉焦点。
- 内容/分析页应让观众先看到页面结论，再看到支撑结论的证据；不要用装饰性图表替代核心信息。
- 收束页应让观众知道要记住什么、决定什么或接下来做什么；页数较少时，可以和最后一个实质结论合并。

## Chart Value Readability（图表数值可读性）

- 少量类别的精确值图表默认逐项展示相关数值；数值可以直接放在图形旁边，也可以放在紧邻图表的结构化数值表达中。
- 不能只依赖柱长、点位、颜色、图例或坐标轴让观众估算关键数值。
- 密集趋势图可以不逐点标注，但至少保留支撑页面结论的关键值，例如起点、终点、峰值、谷值、同比值或异常点。
- 每个定量图表都要明确单位和统计范围；时间序列要说明时间维度，百分比要说明百分比口径。
- 如果数据来自需要追溯的外部研究或证据，在图表附近提供简短来源说明。
- 图表数值必须使用可靠的 Workspace 事实；Preview（预览）中的示意数字只能用于理解结构，不能作为页面事实。
- 没有可靠数据时不要为了填满页面而画图；可以改用明确的事实缺口或不使用图表。

## Formal Presentation Cover（正式汇报封面）

- 只有 Deck 的用途需要正式汇报封面时才使用它；第一页也可以是开场/导览页或带核心结论的内容页。
- 正式封面通常包含标题、主题/周期、日期和演示身份。只使用用户、Workspace 或当前提示词提供的信息。
- 用户未提供汇报人或组织时，默认演示身份是 `ANNA AI`。
- 不要为了填充封面而补造人物、组织、日期、周期或其他业务事实。
- 封面可以省略页码、复杂页眉和正文图表，但必须保留清晰的标题层级和场景识别。
